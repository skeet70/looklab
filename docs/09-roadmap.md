# 09 — Roadmap

Phases are ordered by dependency. Each task has an ID, the docs it implements and acceptance criteria (AC). Tasks in a phase can run in parallel unless they list `deps`. Thresholds marked *(tentative)* should be revisited once real data exists. Record any change in the doc and in the PR.

A native-family target whose pool has fewer than two independent capture groups publishes with no supported probe as an experimental source-limited target: it is discoverable, previewable and usable through experimental matching under the rule in [02 §5](02-color-pipeline.md#5-uncertainty), while a qualified result never uses it. Until P1.9 resolves, cross-body generalization, admission and transfer claims stay experimental under the shared-θ premise ([10 Q18](10-open-questions.md)); the reference body's same-camera native and control qualification can still pass, publication status and rooted trust are separate axes, and a source-limited family keeps refitting its existing seed cohort under unchanged gates. Subject identities and selection semantics are defined in [03 §1](03-data-model.md#1-entities) and [04 §1](04-matching-and-export.md#1-matching-levels); release safety stays in [05 §8](05-trust-and-integrity.md#8-release-gates-and-rollback).

**Cross-body-qualified shared-family launch** additionally requires P1.9 passed and the P4.2–P4.4 numerical and qualification acceptance, including P4.3's engine qualification, with scoped automatic promotion and invalidation through P6.2–P6.3. Neither release claims a camera-wide qualification; measured status stays scoped to settings, encoding and assessed domain. P3.6 and P6.7 can follow shortly after. The queued copy review and documentation-derived camera catalog are independent of the working-fitter release.
